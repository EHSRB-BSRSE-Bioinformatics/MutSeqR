# AGENTS.md

## Purpose

This repository contains the R package `MutSeqR`, which supports import,
cleaning, summarization, statistical analysis, visualization, and reporting
of error-corrected sequencing (ECS) mutation data for mutagenicity
assessment.

Agents working here should optimize for:

- preserving Bioconductor/R package conventions
- keeping import workflows robust to real-world mutation data
- avoiding regressions in downstream summary/report workflows
- making small, well-scoped edits unless broader refactors are explicitly requested

## Repository Layout

- `R/`: package source code. Most feature work belongs here.
- `man/`: generated Rd documentation. Do not hand-edit.
- `tests/testthat/`: unit tests for package behavior.
- `vignettes/`: long-form user documentation and workflow examples.
- `inst/extdata/`: shipped templates, example files, config YAMLs, and helper assets.
- `pkgdown/`: website assets.
- `README.md`, `NEWS.md`, `DESCRIPTION`, `NAMESPACE`: package metadata and top-level docs.

## Package Shape

The package is organized around a practical ECS analysis pipeline:

1. Import mutation data from VCF or tabular formats.
2. Normalize/annotate mutation records.
3. Join sample metadata and optional genomic region metadata.
4. Populate sequence context from a `BSgenome` package when needed.
5. Filter or summarize mutations for mutation-frequency and spectra analyses.
6. Run modeling, spectra comparison, signature fitting, and plotting workflows.
7. Export results or render a standardized summary report.

The introduction vignette at `vignettes/MutSeqR_introduction.Rmd` is the best
single source for expected user-facing workflow and terminology.

## Key Files And Responsibilities

- `R/import_vcf_data.R`: VCF import pipeline. Reads single files or directories,
  extracts INFO/FORMAT fields, joins metadata, creates `GRanges`, populates
  context, characterizes variants, and computes depth-related columns.
- `R/import_mut_data.R`: tabular-data import path with a similar downstream shape.
- `R/import_helpers.R`: helper utilities used by the import layer, including
  sample metadata handling, column normalization, VCF sample-name recovery, and
  VCF end-position derivation.
- `R/load_regions_file.R`: region metadata ingestion.
- `R/filter_mut.R`: mutation filtering logic used before downstream summaries.
- `R/calculate_mf.R`: mutation-frequency calculations across different grouping
  levels and subtype resolutions.
- `R/model_mf.R`, `R/bmd_proast.R`, `R/spectra_comparison.R`,
  `R/signature_fitting.R`: statistical analysis layer.
- `R/render_report.R`: standardized R Markdown report workflow.
- `inst/extdata/Summary_report.Rmd`: report template used by `render_report()`.
- `inst/extdata/inputs/*.yaml`: report/config templates.

## Working Conventions

### R package conventions

- Prefer roxygen comments in `R/` source files; regenerate docs rather than
  manually editing `NAMESPACE`.
- `NAMESPACE` is generated by roxygen2.
- Keep exported function interfaces stable unless the task explicitly calls for
  API changes.
- Follow the existing style: base R plus tidyverse/Bioconductor idioms, with
  explicit namespace qualification used frequently in import code.

### Data model expectations

Across import paths, downstream code expects mutation records to converge on a
common schema centered on columns such as:

- `contig`, `start`, `end`, `ref`, `alt`, `sample`
- context/normalization columns such as `context`,
  `normalized_context`, `subtype`, and `normalized_subtype`
- depth-related columns such as `alt_depth`, `total_depth`, `ref_depth`, `vaf`
- bookkeeping columns such as `variation_type`, `row_has_duplicate`,
  `filter_mut`

Changes to import behavior should be checked for downstream impact on:

- `filter_mut()`
- `calculate_mf()`
- plotting helpers
- `render_report()`

### Import-specific guardrails

The import layer is intentionally defensive. Preserve or extend that behavior.
Important themes from the current code and vignette:

- VCF files are expected to be single-sample per file.
- Directories of VCFs should bind cleanly.
- INFO/FORMAT fields should be retained where possible.
- Sample metadata joins rely on an exact `sample` column.
- Sequence context may come from existing input data or from `BSgenome`.
- Region metadata may be supplied as files, data frames, or `GRanges`.
- Structural variants may require explicit handling of `INFO/END` or `SVLEN`.
- Missing depth columns are tolerated, but downstream capability may be reduced.

When editing import logic, be careful not to break support for:

- bgz/gz VCF inputs
- no-variant records
- symbolic alleles and structural variants
- sample name recovery from either INFO fields or VCF header sample names
- metadata joins with optional sample-name suffix stripping

## Documentation Sources To Trust

When deciding intended behavior, prioritize:

1. `vignettes/MutSeqR_introduction.Rmd`
2. function-level roxygen in `R/`
3. existing tests in `tests/testthat/`
4. examples and templates in `inst/extdata/`

If these disagree, favor the combination of tests plus current package code,
and document any ambiguity in your final notes.

## Testing And Validation

Prefer targeted validation first, then broader checks if needed. The end-user will likely have to run these outside the sandbox, so request it on demand.

Useful local commands:

```powershell
R -q -e "devtools::load_all()"
R -q -e "testthat::test_file('tests/testthat/test_import_vcf_data.R')"
R -q -e "testthat::test_dir('tests/testthat')"
R -q -e "devtools::document()"
R -q -e "devtools::check()"
```

Additional practical checks:

- use small shipped examples in `tests/testthat/testdata/`
- use `ExperimentHub`/`MutSeqRData` examples when reproducing vignette workflows
- verify that changes in import code still produce a usable object for
  `calculate_mf()` and `render_report()`

## Common Edit Patterns

### If you change exported functions

- update roxygen comments
- regenerate documentation
- add or update tests
- check for vignette/example drift

### If you change import behavior

- review both `import_vcf_data()` and `import_mut_data()` for parity where appropriate
- check helper functions in `R/import_helpers.R`
- verify expected columns and types after import
- add a regression test for the specific edge case

### If you change report behavior

- inspect `R/render_report.R`
- inspect `inst/extdata/Summary_report.Rmd`
- inspect YAML/config expectations in `inst/extdata/inputs/`
